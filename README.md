# 秋招雷达 · Qiuzhao Radar（2027 届）

> 一个给自己用的秋招信息中枢：重点公司官方动态、投递进度、面经库和 AI 面试助手，全部集中在一个页面里。
> 纯静态站点，改完数据刷新即生效，支持 GitHub Pages 一键部署。
>
> [English version →](README.en.md)

## 这是什么

秋招雷达是我为 2027 届秋招做的个人工具，解决三个问题：

1. **信息太散**：秋招公告分散在各公司官网、公众号、高校就业网，漏一个就错过一个。
2. **进度太乱**：投了哪些、投了什么岗、到哪一步，很容易记混。
3. **准备无抓手**：面经、通用问题、公司定制提示散落在各平台，收藏了也没时间整理。

所以我把它们做成了四个板块：**总览**（官方公司动态）、**我的投递**（进度管理）、**朱迪汇总**（第三方线索）、**面经库 + AI 建议**（面试准备）。

## 给谁用

- 正在准备 2027 届秋招、目标是 **人力资源 / 游戏运营 / 游戏发行 / 游戏营销 / 用户研究 / 游戏策划** 等岗位的同学（作者本人：应用心理学本科，9 月赴港读研）；
- 任何秋招求职者都可以当作信息聚合与线索参考——但投递前请以公司官方页面为准。

## 核心功能

### 总览（雷达主视图）

- 82 家重点公司官方信息（互联网 / 科技 / 游戏 / 车企），显示行业、批次、岗位方向、开始/截止时间、状态；
- **已投公司置顶**，再按岗位优先级排序：人力资源 > 游戏运营 > 游戏发行 > 游戏营销 > 用户研究 > 游戏策划；
- 状态徽章（进行中 / 即将截止 / 即将开启 / 已结束 / 待核实）和批次徽章（提前批 ⚡ / 正式批 / 补录）都有颜色和动效；
- 截止倒计时、招聘窗口进度条、「最近节点」提醒横幅（14 天内截止、7 天内开启自动汇总）；
- 支持按行业、岗位、批次、状态筛选，一键筛选「重点公司在招 / 即将截止 / 提前批 / 已投」，可隐藏已投、过滤实习。

### 我的投递

- 与桌面 `秋招简历投递.xlsx` 同步（当前 109 条记录，更新表格后告诉 Codex 即可重新导入）；
- 看板 / 表格 / 时间线三视图：时间线日历集中展示笔试、面试、测评等日程，按日期分组并高亮「今天 / 明天 / 倒计时」，支持已完成状态置灰；
- 看板 / 表格支持阶段管理（已投递 / 笔试 / 面试 / Offer / 已挂）。
- 每条投递都有「官网查进度」直达链接：京东、米哈游、B站、巨人、鹰角等已配置官方「投递记录/应聘记录」页，其余公司跳到官方校招入口，登录即可查状态。

### 朱迪汇总（第三方线索层）

- 3027 条岗位记录 + 300 条内推码（2026-08-22 最新导出），可按公司/岗位搜索、按行业/批次筛选、过滤实习；
- 总览页会自动合并朱迪表中互联网 / 游戏行业的目标岗位公司（覆盖运营、发行、营销、HR、用研、策划、市场、品牌等方向），互联网/游戏公司一有相关岗位更新就会自动进入总览。

### 面经库 & AI 面试助手

- 85 条面经（73 条来自《面经分享.pdf》的企业面经 + 12 条真实链接），挂在对应公司的详情页，也可以在面经库页筛选；
- 70 道通用面试问题（来自《校招面试通用常见问题及参考答案.pdf》），含考查意图、回答思路和参考答案；
- AI 建议：10 条面试锦囊 + 30 家重点公司定制提示；
- 「问 AI」按钮会基于你的背景生成一段提示词，复制到任意 AI 对话即可获得个性化回答（纯静态站点不直接调用 AI 接口）。

### 其他板块

- **央国企名录**：119 家央国企与事业单位，含官方网址；
- **信息源**：21 个精选账号（小红书 / 公众号等），分岗位信息、行业面试经验两类；
- **反馈池**：面经 / 内推 / 资讯链接聚合（只存链接和摘要，不搬运原文）；
- **待确认队列**：官网自动检测发现的变化，人工核实后才进正式数据。

## 数据政策（为什么可以信）

- **L1 官方层**（`data/companies.js`）：只收录公司校招官网、官方公众号、高校就业网发布的公司官方信息；未核实的字段一律标「待核实」，不猜日期；所有官方链接已逐一验证可访问。
- **L2 线索层**（`data/zhudi.js`、`data/sources.js`）：朱迪学姐汇总表、小红书推荐账号等，用来发现机会和准备面试，不代表官方数据。
- **L3 面经/反馈**（`data/interviews.js`、`feedback`）：只存链接 + 摘要，保留原文关键细节，不搬运全文。
- `data/applications.js` 由你的 Excel 生成，不要手改。

## 快速开始

**本地打开**

```bash
git clone https://github.com/xhysnd666-alt/Qiuzhao-Radar.git
cd Qiuzhao-Radar
npx serve .
```

也可以直接双击 `index.html`（数据全在本地文件里）。

**部署到 GitHub Pages**

1. 仓库 Settings → Pages → Build and deployment → Source 选 **GitHub Actions**；
2. 推送 `main` 分支后，`.github/workflows/deploy-pages.yml` 会自动部署；
3. 访问 `https://xhysnd666-alt.github.io/Qiuzhao-Radar/`。

## 配套 Codex Skill（让 AI 帮你维护）

仓库里带了一个 Codex 技能：`.codex/skills/qiuzhao-radar/`，让 AI 助手按固定流程维护这个站。它有三种模式：

- **模式 A · 首次设置**：根据简历和偏好初始化用户画像与公司定制提示；
- **模式 B · 每日更新**：官网变化检测 → 官方来源核实 → 更新数据 → 校验 → 提交推送；
- **模式 C · 投递进度**：从 Excel 重新生成投递记录。

**日常操作示例**

| 你说 | AI 会做 |
| --- | --- |
| 「跑一次今天的秋招」 | 自动跑模式 B，更新完推送到 GitHub |
| 「我投了 XX / 更新投递表格」 | 重新导入 Excel，同步投递记录 |
| 把「秋招简历投递.xlsx」或朱迪汇总表 xlsx 发给我 | 自动导入投递/岗位，符合需求的进总览，并推送到 GitHub |
| 「加 XX 公司 / 检查官网链接」 | 验证官方入口后可访问再入库 |
| 「更新面经」 | 解析你发的 PDF / 链接，整理进面经库 |

**GitHub Actions 定时任务**

- `deploy-pages.yml`：每次推送自动部署；
- `daily-update.yml`：每天 UTC 17:00 检测官网变化（需配置 `DEEPSEEK_API_KEY`，否则跳过）；
- `sync-feishu.yml`：每天同步飞书多维表格到「待确认」队列（需配置飞书 App 密钥）。

## 怎么改数据

编辑 `data/companies.js` 里的 `companies` 数组，字段说明：

| 字段 | 说明 |
| --- | --- |
| id | 唯一标识，英文小写 |
| name / industry | 公司名 / 行业 |
| batch | 提前批 / 正式批 / 补录 |
| startDate / endDate | YYYY-MM-DD，未知留空 |
| status | 进行中 / 即将截止 / 即将开启 / 已结束 / 未开始 / 待核实 |
| positions | 岗位方向数组 |
| applyUrl / careerUrl | 投递链接 / 校招官网 |
| note / source / verified | 备注 / 信息来源 / 是否已验证 |

修改后刷新页面即可看到效果；提交前可运行 `node --check js/app.js` 做语法检查。
